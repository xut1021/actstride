两对都成功的端到端耗时比中位数为 **1.72**，但只有两个配对，不能据此宣称普遍提速。规划模型启动、传输及生成用时也有波动，不能把全部时间差归因于少了两次快速决策。试跑中无技能为 **2/3 次已启动运行成功**；有技能为 **2/2 次已启动运行成功，另有 1 次 skipped**。样本和网络条件不足以证明成功率提升，失败不会从分母中剔除。

通知诊断又暴露了完整流程与其第一步都可推进任务的歧义。目前进一步明确：流程可以直接启动，会自行打开所需面板；原子动作只执行一步。仍保留全部候选及 0.55 阈值，不把两个选项的概率相加。**这次进一步措辞调整只有本地验证，尚未进行真实模型复测；上表的结果对应之前的试跑版本。** 日志现在保留原始候选概率，便于继续检查这个问题。

实验脚本新增同模型技能配对、场景选择、重复次数和预算参数，交替组别顺序，保存每个已开始的尝试，并在各次运行前后核对源码冻结状态。401/403 权限拒绝或额度错误会停止整批；未完成组合不会算作通过。

`--reconcile-usage` 是可选的汇总费用核对：开始时保存提供方用量基线，失败后用提供方已入账总额减去基线和已记账支出。只有差额在现有预留内才能结算；用量缺失、减少、未涵盖已记账支出或差额超出预留时，保留待结算状态并停止后续付费调用。它是保守的汇总归账，不是单请求发票，也不重试已失败的推理。提供方入账可能有延迟，汇总核账不等于服务端硬限额。建议使用项目独立密钥；其他程序共用密钥可能使汇总无法归因。

当前本地检查：接口、实验调度及记账 **55/55**；针对性的浏览器衔接 **2/2**；无 API 审计 **33/33**。实验调度测试使用隔离临时目录和模拟服务，不访问真实模型。
