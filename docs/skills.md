# 参数化技能 v1

这版把「规划模型提取任务参数 → 快速模型选择流程 → 执行器逐步操作 → 独立验证」接入现有控制器。技能默认为关闭，使用 `--skills` 启用，当前仅支持 Codex 规划器加双模型模式。

## 三个流程

| 技能 | 输入 | 执行前提与操作 |
|---|---|---|
| `assign_ticket` | department、priority、owner | 工单页面，部门和优先级匹配唯一一行；打开、设置负责人、核对、确认 |
| `book_room` | day、period、capacity、name | 预约页面，可用房间唯一满足时间和最小容量；选择、填申请人、核对、确认 |
| `notification_preferences` | email、sms、zone | 偏好页面；打开通知面板，按目标状态调整开关和时区，核对并确认 |

参数只能由规划模型从当前任务提取。技能代码不读取 `scenarios.mjs`、隐藏配置或测试答案，不使用固定工单编号、房间编号和屏幕坐标。它依赖当前站点的中文标签、行/卡片语义和确认格式，尚不是跨网站技能。

`skills.mjs` 声明参数格式和页面范围；`skill-runner.mjs` 是有限、可审查的流程实现。规划器获得当前页面的简短技能目录。有效参数绑定后，System 1 的原子动作候选中加入 `use_skill`；没有绑定或页面不适用时不提供该选项。规划器自身不能直接返回技能执行动作。快速后端可替换，技能执行器与退出条件不变。

## 执行与退出

所有模式共用 `browser.mjs`：语义 click/fill/select 使用元素 ref 和 revision；滚动可以省略坐标。引用在页面内保持稳定，文档重载、元素替换、值或选项变化会使旧动作失效。动作执行前检查目标是否可用、是否仍属于当前弹窗、是否被遮挡。布局可见但在视口外的控件允许滚入视口后操作。

每个技能步骤重新读取 UI。填表和选择后核对实际值，开关已正确时不重复点击。确认摘要必须匹配参数，确认框只能包含预期的两个按钮；额外输入框、密码框、多行文本框等都会中止流程。歧义、缺选项、状态变化或独立验证失败返回 `replan: true`，控制器立即清除绑定并交回规划器。部分已完成动作不回滚，规划器收到的是当前现场和失败原因。

技能不运行模型生成的代码。步骤成功执行并不等于任务完成，最终仍由原有独立验证器决定是否通过。实际部署到其他页面时，需要另行定义适用范围和独立验收方法。

## 经验记录

CLI 将 `skill_start`、每个已执行的 `skill_step` 和 `skill_result` 写入该次运行的 `events.jsonl`。`runs/skills/experiences.jsonl` 保存任务、绑定参数、成功/失败原因、步骤数及对应运行路径。失败也保留，便于提炼前比较。

当前三个技能是手工编写的；记录不会自动变成可执行技能，没有模型训练、自动归纳或长期检索。后续归纳流程应产生候选，再用独立的变化任务验证后启用，不能根据一次无异常执行就自动推广。

## 复现

```sh
# 不调用真实模型：实际浏览器测试 + 模拟路由响应
npm test
npm run audit

# 真实订阅规划模型绑定参数，直接检查技能执行；不调用 Jev
node scripts/skill-planner-check.mjs --channel msedge

# 完整双模型技能路径，会消耗 OpenRouter 和订阅额度
npm start -- --mode dual --scenario tickets_b --skills --headless --channel msedge

# 三组配对实验：仅规划、双模型无技能、双模型有技能
node scripts/benchmark.mjs --skills --channel msedge
```

使用 Edge 跑测试时，PowerShell 先执行 `$env:FCU_TEST_CHANNEL='msedge'`。默认测试浏览器为 Playwright Chromium。

三组实验共享观察数据、原子动作、独立验证器和规划器启动方式，按场景轮换组别顺序。技能内部步骤单独计数，日志包含失败与耗时。当前每个组合只有一次尝试，最多 24 次外层决策；这是初步配对实验，不是稳定性统计。技能组一次决策可执行多步，因此同时比较实际动作数和限额失败，不能只比较外层决策次数。

## 验证边界

2026-09-26 最终回归：54/54 测试通过，其中新增技能测试 20 项；无 API 审计 33/33 通过。九个正向技能用例包含六个已有场景及三个新参数、重排/位移布局组合，其余技能测试覆盖过期引用、页面重载、重复目标、不可用选项、变化的弹窗、遮挡、已有正确状态和控制器交接。

真实订阅规划检查 3/3 通过：工单、预约、通知设置各一次。每次规划器均返回正确参数绑定，执行器完成四个页面动作并通过独立验证。这里没有调用真实 Jev；不把三次检查计为完整双模型成功率。最终额外字段和文档引用保护是在这三次检查后补充的，并通过最终浏览器回归；JSON 保留各阶段源码哈希。

验证数据见 [skill-validation.json](skill-validation.json)。测试中的新参数与布局是检查手工流程的泛化边界，不是独立采样的通用网站基准。全双模型技能路径的路由测试使用模拟 Jev 响应；订阅规划器的真实检查直接调用技能执行器，没有假装使用真实 Jev。

本轮没有新增 OpenRouter 调用。此前请求仍有未结算预留，费用账本保持不变；因此三组真实对照尚未执行，不能给出新增技能后的提速倍数。历史实验使用的是旧执行接口，也不能直接当作这版的无技能基线。
