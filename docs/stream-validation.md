# 在线工单流：Jev 替代后续 Astra 判断的配对结果

日期：2026-09-27。[运行前方案](stream-experiment.md) · [四次完整脱敏记录](stream-validation.json)。

**在这个合成在线任务里，双模型与 Astra 对照均为 16/16 正确、整批 2/2 通过；双模型每批只需 2 次 Astra，对照为 9 次。** 完整任务耗时中位数从 176.03 秒降至 41.69 秒，描述性比值 4.22，少用 76.3% 时间。它支持在这个工作流中继续研究分工，不证明复杂任务普遍提速或提高准确率。

## 任务和分工

选题参考 [WorkArena++](https://github.com/ServiceNow/WorkArena) 的组合业务流程。实际为本项目新编写的 8 张合成工单，依次出现，包含引用文本干扰、否定语义、历史事件去重、信息不足和第 5 张开始生效的队列规则变更。不是 WorkArena 数据、代码或官方成绩。

Astra 首次只看源策略和公告，不知道未来工单内容，也没有给 Jev 逐题答案。Jev 此后读取编译策略、当前新工单、最新公告和实际已处理历史，从 6 个队列技能或 escalate 中选择。低置信度或者 escalate 才调用 Astra；Astra 可判断当前工单并更新后续策略。

两组使用完全相同的 routeSkill：点击所选队列、验证确认框的工单 ID 与队列、确认，之后读取下一张。每批 8 次 Skill、17 次实际 UI 输入（含开始按钮）。执行器不判断分派是否符合业务规则；整批结束后才读取 fixture 的私有期望队列并核对，执行器完成不等于业务正确。

两轮均只有第 5 张请求 Astra：Jev 主动返回 escalate，所选概率分别 0.56、0.62。代码没有“到第 5 张就升级”的规则，也没有强制按公告版本交回 Astra。Astra 将普通锁定的分派从 Access 修订为 Identity，正确处理当张；Jev 随后自行选择 ServiceDesk、Duplicate、ManualReview。这里 ManualReview 是业务队列，不是再次调用 Astra。

两批的队列轨迹均为 Security → Access → ServiceDesk → Access → Identity → ServiceDesk → Duplicate → ManualReview。实际回执、动作记录与结果一致；首批最终截图也显示 PASS。16/16 是同一组 8 个样例各测两次，不是 16 个独立新任务。

## 能说明什么，不能说明什么

- 与上一轮“让 Jev 再确认 Astra 已绑定的 Skill”不同，此次 Jev 真正承担了后续局部决策。每批避免了 7 次 Astra 请求，调用数少 77.8%，这解释了主要速度收益。
- 当前发现的适用条件是：新输入陆续出现、不能提前一次读完；策略可复用；有稳定的候选技能；大多数输入能按现有策略处理，少数变化需要升级。任务整体长不等于每个局部判断都应交给大模型。
- 这是单一小型人工样例、两次重复。两组都全对，没有准确率提升证据；也未验证跨应用、开放式规划、更长依赖链或更难例外。
- 两组各自生成初始策略，措辞可能不同；原文保留在 JSON。Astra 判断可以重新读取源策略，Jev 使用编译策略，输入分工不是完全相同。
- 对照是一次策略编译＋逐单 Astra，每次返回选择及策略文本，CLI 每次独立启动。不是经过所有优化的最强 Astra 系统。不能据此否定持久会话、较短输出、批量处理、规则引擎或其他快速模型；未加入 Jev 独立阅读源策略组，也不能证明 Astra 的策略编译不可替代。
- 4.22 是这四次运行的中位数比，不是模型纯推理速度比或可保证的长期加速倍数。0.55 阈值未校准；本轮的正确升级不证明将来每次都能识别越界。

## 环境、费用和失败记录

实际后端是 Playwright＋Edge 无头浏览器，输入为可见 DOM 文本，**不是原生 sky，也不是 Windows UIA 成功测试**。运行前 UIA 新场景及旧场景均在首次观察时超时，检测到 LockApp；停止桌面输入后改为独立浏览器。没有给桌面故障记模型失败或通过，也没有尝试解锁桌面。

本地执行测试 2/2 通过，其中浏览器测试包含一遍 8/8 正确分派和一遍故意错分后的 7/8，验证评分器会拒绝错误整批。真实模型四次运行没有网络失败、跳过或重跑，前后运行源码哈希一致。

Astra 为订阅 gpt-6-astra / medium，Jev 返回 typesafe/jev-1.13-20260917。新增 OpenRouter 费用 **$0.000555912**；共享累计 **$0.043318505 / $20**，pending=0。Astra 的订阅用量单列在 JSON，不算免费 API。

任务时间含初始策略、后续模型请求、技能执行和最终独立回执读取；不含浏览器启动、最后截图和清理。该 fixture 未向外部发送工单，只将合成文本发送给已授权模型服务。完整原始记录保存在本地 runs/；公开 JSON 去掉了提供商请求标识。

复现：`node windows/stream-benchmark.mjs`。需要 Edge、已安装依赖、已有 Codex 订阅登录及授权 OpenRouter 密钥；固定执行上述四个单元，会产生真实用量。用户日常原生 Computer Use 的默认路线未改动。
