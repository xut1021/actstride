# 独立 Windows 桌面执行器

这是 ActStride 的 UI Automation 桌面实验后端。它启动真实 Windows Forms 窗口，由另一个进程读取 Windows UIA 控件、通过 `ValuePattern.SetValue` 填写、通过 `InvokePattern.Invoke` 点击功能按钮。没有调用官方 Codex Computer Use helper，也没有改动其插件或执行规则。

当前范围刻意限定为随仓库提供的 `ActStride Desktop Lab`，驱动会检查目标进程的可执行文件和窗口名称；不能传入记事本、浏览器等个人应用来宣称通用支持。这是结构化控件辅助的桌面操作，不是纯截图模型，也不是通过网页 DOM 模拟桌面。

首轮[真实三组对照](windows-validation.md)共 12 次，全部通过：任务中位时间从逐步组的 150.9 秒降至技能组及双模型技能组的约 32.6 秒。增加 Jev 的独立提速收益尚未得到证明。数字包含每次 Codex CLI 的启动/退出开销，只适用于这套原型和测试任务。

## 执行流程

规划模型读取当前可见控件结构。逐步组每次返回一个动作；技能组一次绑定所有字段。技能执行器逐步重新观察，检查字段值、唯一目标、确认内容及提交状态。检查不需要再次调用规划模型。双模型技能组在执行技能前由快速模型判断是否适用，低置信度则退回逐步规划。

第一版使用有期限的 UIA 状态轮询（每 40 毫秒检查一次，通常首次即满足），**没有实现 UIA 事件订阅**。截图只用于完成后的证据，不在每步重复生成；独立验证由测试应用写出的实际提交回执完成，回执不进入模型输入。

两个任务族为物料单和房间安排，每族有不同字段值、不同控件排列的 a/b 版本。所有提交只发生在本地测试窗口，没有实际库存或预约的外部副作用。模型能看到任务要求和可见 PASS，属于透明集成测试。

## 本地验证

需要 Windows、Node.js，以及系统中已有的 .NET Framework 4.x 编译器和 UIAutomation 程序集。使用框架编译器生成 `runs/windows-build/ActStrideDesktopLab.exe`，不下载额外依赖。

```powershell
$env:ACTSTRIDE_WINDOWS_TEST = '1'
try { node --test test/windows.test.mjs test/codex.test.mjs }
finally { Remove-Item Env:ACTSTRIDE_WINDOWS_TEST }
```

这个显式开关会创建并关闭测试窗口。普通 `npm test` 不会自动操作 Windows 桌面。真实 UIA 测试验证旧引用拒绝、字段顺序变化、确认提交，以及修改字段使旧 PASS 和回执失效。

## 三组真实模型对照

确保官方 Codex CLI 已使用 ChatGPT 登录、现有账本上限与参数一致，并通过环境变量提供已授权的 OpenRouter 密钥。不要把密钥写进命令参数或版本库。

```powershell
node windows/benchmark.mjs --cases inventory_a,booking_b --repeats 2 --budget 20
```

同一任务/重复下交替三种模式的顺序：

| 模式 | 规划模型 | 快速模型 | 执行 |
|---|---|---|---|
| stepwise | 每个动作调用一次 | 无 | 每步 UIA 操作与验证 |
| skills | 一次绑定技能；必要时后续规划 | 无 | 同一后端连续执行有检查的技能 |
| dual-skills | 一次绑定技能；异常时逐步恢复 | 一次判断技能适用性 | 与 skills 相同的技能 |

三组默认都使用订阅认证的规划模型，快速模型使用既有 OpenRouter 账本。型号、推理档位、源文件哈希和用量记录在 manifest 及每组事件中。规划请求通过官方 CLI 发起，每次启动和退出开销计入总耗时；没有把这些开销当作纯模型计算时间。

每次运行都从新窗口开始。结果同时记录任务时间、窗口初始化时间、规划耗时、快速模型耗时、UIA 执行时间和实际动作数。所有失败、跳过项及未知费用保留；传输或运行时错误停止该批次，不自动重试模型请求。成功率按全部开始的样本统计，提速比只比较相同任务/重复下均成功的样本。

## 当前边界

- 尚未验证真实第三方桌面软件、自绘控件、视觉回退或用户并发操作。
- 不能只因 UIA 调用返回成功就宣称任务成功；必须等待预期界面变化并检查独立回执。
- 驱动每次操作前会检查目标元素的身份、名称、值、启用及可见状态，消费旧引用后才发出操作。原子检查与输入之间仍可能有竞态，不是操作系统级事务。
- Escape 在驱动发出动作前检查；当前没有持续全局中断监听。测试窗口和驱动由运行器创建与清理，不应扩展到个人应用而沿用这一简化生命周期。
- 这是实验后端。技能相对逐步规划的收益，以及增加快速模型的增量收益，需要分别报告；不能把前者全部归功于双模型。
